# HyperSecure — демонстрація для уроку

> ⚠️ **Це навмисно зламаний генератор ключів для навчання. Ніколи не використовуйте його ключі для чогось справжнього.**

Сайт називає себе «найбезпечнішим генератором ключів у світі»: квантовий захист,
військовий рівень, нульове розголошення, відкритий код, шкала ентропії та зелена
оцінка «НЕЗЛАМНИЙ ✅». Його ключі виглядають випадковими і пройшли б статистичні
тести на випадковість.

Але він може видати лише **4 096 різних ключів**, і кожен, хто прочитає ~100
рядків у [`js/keygen.js`](js/keygen.js), може перелічити їх усі.

**Урок:** реклама, значки, «відкритий код» і випадковий на вигляд результат
нічого не гарантують. Треба читати код або довіряти тому, хто його справді прочитав.

## Що з ним не так (спойлери для учнів)

Відкрийте [`js/keygen.js`](js/keygen.js) і знайдіть:

| Що обіцяє сайт | Що насправді робить код |
| --- | --- |
| «Справжня ентропія з миші та клавіатури» | `addEntropy()` зберігає події, але їх ніхто ніколи не читає. Шкала ентропії — просто декорація. |
| Ключі на 256/512 біт, «≈ 10^77 можливих ключів» | `ENTROPY_POOL_SIZE = 4096`. Єдине випадкове значення — вибір 1 комірки з 4096, тобто лише 12 біт справжньої ентропії, хоч який розмір ключа ви оберете. |
| «Виконуємо 1 000 000 раундів посилення» | `HARDENING_ROUNDS = 1`, тож цикл посилення ніколи не виконується. Список етапів у `ui.js` — анімація з таймером. |
| «SHA-256 військового рівня» | Сам SHA-256 надійний, але його застосовують до публічної солі та номера комірки. Геш від передбачуваних даних дає передбачуваний результат, який лише *виглядає* випадковим. |
| «Криптографічно безпечно» | Комірку обирають через `Math.random()`, а це не криптографічний генератор випадкових чисел. Тут це майже не важливо, бо комірок усе одно лише 4096. |
| «Код відкритий, отже безпечний» | Відкритий код допомагає лише тоді, коли його хтось справді читає. |

Правильний генератор просто викликає `crypto.getRandomValues(new Uint8Array(32))`.

## Як провести урок

1. Покажіть головну сторінку. Нехай учні порухають мишею, щоб заповнити шкалу ентропії, і згенерують ключі. Запитайте: *чи довірили б ви цьому сайту?*
2. Нехай хтось згенерує ключ і надішле його в чат або напише на дошці.
3. Відкрийте **`crack.html`** (на головній сторінці посилання немає) і вставте ключ. Його буде знайдено миттєво, разом із номером комірки.
   Можна також запустити `python3 tools/crack.py <ключ>` або `python3 tools/crack.py --list`.
4. Разом відкрийте `js/keygen.js` і знайдіть вади з таблиці вище.

Бонус: згенеруйте на сайті 100 ключів. Через парадокс днів народження ймовірність,
що два з них збіжуться, становить близько 70%.

## Файли

- `index.html`, `style.css`, `js/ui.js`: переконливий інтерфейс
- `js/keygen.js`: «рушій», у якому й сховані вади
- `crack.html`: сторінка атакувальника, яка заздалегідь обчислює всі 36 864 варіанти (4096 комірок × 3 розміри × 3 формати)
- `tools/crack.py`: та сама атака з командного рядка

Збирати нічого не треба. Це звичайні статичні файли, які GitHub Pages віддає з кореня гілки `main`.
